# dsh-wait-reply

让根会话在准备结束时，等自己已经启动的子智能体结果回到**同一轮**，再整合并收尾。不用指定角色，不用切换智能体团队，也不用每次提醒“请等待”。

已在 DSH `0.2.2-rc.1` 的隔离运行时验证。官方若提供同等能力，停用或卸载本插件即可。

## 行为

插件只做三件事：

1. 根会话即将结束、下一步收件箱还是空的、且没有被取消时，调用宿主已有的 `subagents.waitForChildren`。
2. 子结果或用户的下一步输入到达后，把控制交回原来的轮次。若仍有子工作，下次准备结束时再等。
3. 随插件加载一段内部指导，说明子结果留在当前轮，空闲、失败、取消都不等于任务成功。不需要改 `AGENTS.md`。

它不新建消息，不改消息来源，不取消子智能体，不调用目标完成，也不把“能退出等待”当成业务成功。目标工具原有的权限检查保持不变。

`waitForChildren` 没有取消参数。停用时只解除插件自己的等待并卸下监听；宿主那次等待会在子工作结束后自行结束，不会因此取消子智能体。

## 安装

本插件是一个无依赖的本地 bundle。在**不是正在使用的桌面 profile** 上，可以：

```sh
dsh plugin --profile <name> add /absolute/path/to/dsh-wait-reply
```

正在运行的 DeepSeek Harness 桌面端独占 `desktop` profile，应用内应使用 **设置 → 插件** 从本地目录安装。完全退出应用后，才可以用上面的命令管理该 profile。

只验证过 DSH `0.2.2-rc.1`。版本或 `waitForChildren` 接口不匹配时，插件保持未激活并写一条警告，会话回到原生收尾，不会阻止 DSH 启动。

## 关闭

在设置里停用插件行 `dsh-wait-reply`。有热重载的环境会立刻解除插件正在进行的等待、去掉监听和内部指导，之后的轮次恢复原生收尾。子智能体不会被插件取消。

没有热重载时，插件管理器会报告需要重启。等待要到插件真正卸载才解除，不要假定所有环境都能热停用。

关闭插件**不会**改回“收起后显示的回复”。那是 DSH 自己的偏好，按轮次生效，不能合并已经分开的多个轮次。需要的话可手动设为“仅最终回答”；它只影响显示，不代替本插件。

## 卸载

在设置里移除 bundle `dsh-wait-reply`，或在 profile 未被正在运行的桌面端占用时：

```sh
dsh plugin --profile <name> remove dsh-wait-reply
```

卸载同样不取消子智能体，也不删除已有会话记录。

## 已验证

隔离 profile、本机原装宿主、脚本模型，没有调用付费模型，也没有改正在使用的 DSH：

- 通过 bundle patch 由加载器启动，而不是测试代码直接调用 `apply`
- 有目标、分批结束的两个子智能体：一次正常收尾，目标完成权限保留
- 无目标、无子智能体、等待中用户插话、子智能体失败、用户取消
- 等待过程中停用插件：等待解除，子智能体继续运行
- 再次启用后仍能并回同一轮
- 停用 bundle 后恢复多次原生收尾
- 版本不匹配的夹具 bundle 被跳过，不阻止启动
- 接口或版本无法确认时，`apply` 不注册监听

## 未验证

以下不能当成已支持：

- 真实 Grok 或桌面界面上的最终显示。模型仍可能先写出进度文字；插件不撤回已经流出的正文
- “仅最终回答”的真实界面效果
- 后台 Bash 作业、审批、模型 token 上限、复杂嵌套、外部子智能体后端、应用重启后的恢复
- 没有热重载的 profile 上，等待过程中的即时热停用
